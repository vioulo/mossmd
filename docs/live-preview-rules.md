# 实时预览交互规范

本文档定义 MossMD 编辑模式下 Markdown 源码的显隐规则。它是装饰实现和回归测试的行为基准，优先于某个具体的 CSS 或 CodeMirror API 实现。

## 基本模型

实时预览需要区分三个状态。它们不能合并成一个 `active` 布尔值。

### 编辑器焦点

`editorFocused` 表示编辑器是否真正拥有 DOM 焦点。

- 只有编辑器获得焦点时，才允许显示编辑源码。
- 失去焦点后，编辑器回到预览态；当前选区可以保留，但不能仅凭残留选区显示源码。
- 阅读模式始终禁止源码显露。

焦点是所有显露行为的总开关，不是某一种 Markdown 语法的显露策略。

### 当前行激活

`activeLines` 是选区覆盖的源码行集合。单个光标所在行也属于当前行。

当前行策略适用于“用户需要编辑整行结构”的语法：光标只要进入这一行，该行的结构标记就显示出来。它不应传播到同一行的行内链接。

对于多选区，所有选区覆盖的行都算当前行。当前行状态只影响显隐，不改变 `state.doc`。

### 行内贴近

`nearInline` 表示光标或非空选区与某一个行内语法范围相交，或光标位于该范围的源码边界。

- 空选区使用源码位置判断，边界采用闭区间 `[from, to]`。
- 非空选区使用范围相交判断。
- 不使用像素距离，也不把整行作为“贴近”。
- 一次只应激活光标所在的目标链接；只有非空选区跨过多个链接时，才同时显露多个链接。

这里的“边界”是 CodeMirror 的源码位置边界，不是隐藏 Widget 的视觉宽度。这样可以避免点击相邻内容时同时展开两个链接。

## 显隐分级

每类语法只能选择一种主策略。策略优先级从高到低为：

1. 阅读模式：全部保持预览，不显露编辑源码。
2. 交互冻结：`pointerdown` 到释放尾部期间保持旧装饰，防止源码在鼠标下方突然出现。
3. 行内贴近：链接等局部语法显露自己的源码范围。
4. 当前行激活：行级结构语法显露当前行源码。
5. 非激活状态：保留阅读态 Widget、标记或隐藏语法。

行内贴近和当前行激活同时成立时，行内语法使用自己的局部策略。也就是说，当前行不能覆盖链接策略。

## 当前实现差异

本规范描述目标行为，当前代码仍有以下需要收敛的地方：

- `inline-preview.ts` 已将普通链接的 `LinkMark`、URL 和标题按链接范围处理，但焦点门控、当前行判断和鼠标冻结仍由不同的机制维护。
- `wiki-links/index.ts` 使用独立 `StateField`，目前主要依据选区判断显露，尚未与主实时预览共享同一个编辑器焦点状态和冻结状态。
- Wiki 链接的范围判断需要和普通链接统一为“范围相交 + 源码边界”，并确保一个折叠 Widget 的视觉位置不会把相邻链接映射成同一个激活目标。
- 补全的 `serializeSuggestion` 是插入片段协议，不是完整 Markdown 包装协议；这个约定需要继续保留在公开 API 文档和测试中。

实现这些规则时，优先统一状态模型和范围计算，再调整 CSS 或增加快捷键特判。任何新语法都必须先归类到“当前行显露”“行内贴近显露”或“Widget 优先”，不能默认加入 `activeLines`。

## 语法归类

### 当前行显露

以下语法属于行级结构，光标进入所在行后显露源码：

- ATX 标题前缀：`# ` 到 `###### `。
- Setext 标题下划线。
- 引用前缀：`> `，包括嵌套引用前缀。
- 无序列表标记：`- `、`* `、`+ `。
- 有序列表标记：`1. `、`1) ` 以及其它合法编号形式。
- 任务列表标记：`[ ] `、`[x] `。
- 围栏代码块的围栏和语言信息；点击或进入代码块时按代码块范围保持一致。
- 水平线：`---`、`***`、`___`。
- 行内强调、删除线、高亮和行内代码的定界符。它们是当前行的编辑辅助，不单独触发行内链接规则。
- 转义反斜杠和 Callout 行前缀。

这里的“显露”只表示恢复源码令牌的可见性。行高、列表槽位和包装行几何必须保持稳定。

### 行内贴近显露

以下语法只在光标进入或贴近自身范围时显露源码，光标停在同一行的其它位置时继续保持预览：

- 标准 Markdown 链接：`[label](url)`。
  - `[`、`]`、`(`、`)`、目标 URL 和标题属于同一个链接激活范围。
  - `label` 是可见内容，不因当前行激活而显示额外语法。
  - 光标只在链接所在行的其它位置时，显示 `label`，不显示 `[]()`。
- Wiki 链接：`[[target]]`、`[[target|label]]`。
  - 整个 Wiki 源码属于同一个激活范围。
  - 渲染出来的 label 或 Widget 不能把相邻 Wiki 链接一起激活。
  - 行内代码中的 `[[...]]` 不属于 Wiki 链接。
- 标准链接和 Wiki 链接的激活判断必须使用同一套“范围相交 + 边界”语义。

### Widget 优先

以下内容由独立 Widget 提供阅读态表现，不因为当前行聚焦就直接恢复整段源码：

- 图片块及其编辑控件。
- 表格 Widget 及其单元格内部编辑器。
- 文件块。
- 上传中的临时块。

这些功能如果需要编辑源码，必须通过明确的点击、编辑控件或内部编辑器完成，并保持原文仍是唯一数据源。

## 规则优先级示例

对于：

```text
Labeled: [[demo-project-atlas|Project Atlas]] · Bare: [[demo-meeting-notes]] · In code: `[[demo-project-atlas]]`
```

期望行为如下：

| 光标位置 | 期望显示 |
| --- | --- |
| `In code` 文本上 | 前两个 Wiki 链接保持预览，代码中的 `[[...]]` 保持原文代码表现 |
| `Project Atlas` 内部 | 只展开第一个 Wiki 链接 |
| 第一个 Wiki 链接的源码边界 | 展开第一个 Wiki 链接，不展开第二个 |
| `Bare` 文本上 | 两个 Wiki 链接都保持预览 |
| 代码反引号内部 | 不启动 Wiki 链接解析或 Wiki 装饰 |

对于：

```text
[Render semantic vector](https://example.org/1620e) for more.
```

期望行为如下：

| 光标位置 | 期望显示 |
| --- | --- |
| `for more.` 文本上 | 显示 `Render semantic vector`，隐藏 `[]()` 和 URL |
| label 内部或链接源码边界 | 显示完整 `[Render semantic vector](https://example.org/1620e)` |
| 离开链接后 | 恢复为只显示 `Render semantic vector` |

## 输入与补全

Wiki 补全的触发文本已经包含源码中的开头 `[[`。因此 `serializeSuggestion` 的返回值必须是“开头 `[[` 之后要插入的片段”，并包含结束的 `]]`：

```text
输入：[[ro
补全插入片段：roadmap|Editor Roadmap]]
最终原文：[[roadmap|Editor Roadmap]]
```

回调不能再次返回开头 `[[`，也不能多插入 `}`。补全应用完成后必须把焦点还给编辑器，Home、End 和方向键应继续操作编辑器选区。

## 实现约束

- `state.doc` 永远保存完整 Markdown，显隐只能由 Decoration、Widget 和 CSS 完成。
- 行级语法和行内链接不能共享未经区分的 `activeLines` 条件。
- 标准链接和 Wiki 链接必须分别保留自己的源码范围，但共享激活语义。
- `Decoration.replace` 不能改变源码位置的可预测性，也不能让活动态和非活动态产生不稳定的行高。
- 装饰重建必须响应选区变化、编辑器焦点变化、阅读模式变化和冻结状态变化。
- 每一条规则至少需要一个状态测试；涉及 DOM 坐标、点击或键盘导航的规则还需要真实浏览器测试。

## 回归测试矩阵

最低覆盖范围：

- 当前行其它位置不会展开标准链接或 Wiki 链接。
- 光标进入链接内部或位于链接边界时，只展开目标链接。
- 相邻链接不会因一个鼠标点击同时展开。
- 行内代码中的 Wiki 文本不会被解析成链接。
- 标准链接 label 内含 URL 时，label URL 不会被误判为目标 URL。
- Wiki 补全不会重复 `[[`、不会产生多余 `}`，应用后编辑器仍保持焦点。
- 链接展开后按 Home、End、左右方向键，选区位置和焦点保持正确。
- 编辑模式、失焦状态和阅读模式之间切换后，源码显隐符合上述优先级。
